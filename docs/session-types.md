# Kmap Session Types

更新日期：2026-09-12

Kmap 只使用两种会话类型：`决策会话` 和 `实施会话`。其他名称不得作为会话身份使用；调试、验证、性能分析、审查、重构和迁移都只是任务性质。

## 决策会话

职责：

- 确认产品目标、范围、MVP、架构、数据结构、公共 API 和技术选型。
- 新增、拆分、排序、暂停、关闭或重新定义 Task。
- 处理人工验收与自动证据冲突。
- 处理跨任务污染、旧方案隔离、依赖新增、预算调整和验收门槛变化。
- 更新 `PROJECT.md`、`TASKS.md`、`docs/architecture.md`、`docs/decisions.md` 和任务上下文包。

不承担：

- 日常功能实现。
- 未经任务批准的代码修改。
- 用会话讨论直接替代证据、测试或正式决策。

## 实施会话

职责：

- 围绕一个已批准 Task 工作。
- 按 `Task Context Packet` 的 `Must Read`、`Allowed Files`、`Forbidden Files` 和验收要求执行。
- 实现、测试、调试、性能分析、专项验证和记录。
- 更新当前任务文件、相关 evidence、知识分片和项目状态。

不承担：

- 擅自改变公共 API、核心架构、MVP、任务范围或技术基线。
- 跨越当前 Task 修改无关模块。
- 默认读取旧任务全量历史、完整知识归档或全量 evidence。

## 升级规则

实施会话遇到以下情况必须停止扩大实现，并返回决策会话：

- Task Context Packet 缺失、冲突或无法覆盖必要文件。
- 需要修改 Forbidden Files。
- 需要改变核心架构、公共 API、MVP 范围、技术选型或验收门槛。
- 自动测试通过但人工体验明确失败。
- 旧任务结论会污染新实现路线。
- 需要新增运行时依赖或引入第三方核心方案。

## 命名规则

- `TASKS.md` 的会话列只能填写 `决策会话` 或 `实施会话`。
- `docs/ai-sessions/` 的会话记录只能填写 `决策会话` 或 `实施会话`。
- 任务性质写入标题、Scope、关联范围或 Findings，例如“性能基线”“人工验收”“调试修复”，不新增会话身份。
