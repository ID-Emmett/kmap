# 瓦片重叠与大倾角调度审计

日期：2026-09-15。对象：当前 `StreamingEngine`。本文件记录已验证事实与证据边界；实施建议见 [优化方案](../ai-sessions/2026-09-15-tile-optimization-proposal.md)。

## 结论

1. 当前目标集合采用混合 LOD。同一画面中的 z13、z14、z15 可以分布于互不重叠的地面区域。
2. 当前实际绘制集合允许父子瓦片覆盖同一区域。确定性复现确认同一区域同时提交 z12、z13、z14，三者 opacity 均为 1，已超过 140 ms 淡入期。
3. 大倾角下的近处细节受选片上限与预算合并影响。北京、zoom 15、pitch 60°、bearing 0°、2560×1305 的目标为 z13×15、z14×61、z15×3；屏幕下方约 1/3 的地面采样中，99.1% 落在 z14 目标。
4. 当前雾与加载半径有关联，但该视图完全入雾的屏幕采样约为 2.9%。预热还包括截止半径内的全方位与多级祖先需求。
5. 当前面板的层级、过渡、覆盖和内存指标具有明确的统计边界，尚缺逐区域实际绘制层数、近处质量和无效工作的证据。

## 父子瓦片实际怎样叠加

`selection.ts:40` 的预算合并产生空间互斥的目标。`engine.ts:287` 的 `resolveCover()` 对每个目标寻找可用数据，并把来源瓦片加入 `next`。一个父级为某个未就绪区域提供覆盖时，会以完整瓦片范围绘制，同时与相邻已就绪子瓦片相交。

`surface.ts:25` 的材质使用 `depthTest=false`、`depthWrite=false`、`transparent=true`；`renderOrder=z*2`，道路为 `z*2+1`。完整面纹理包含背景色。较高层级可以在最终颜色中遮住父级，但父级的绘制与纹理采样仍会发生。当前缺少父级剩余区域裁剪或瓦片所有权模板遮罩。

CPU 复现：

| 当前目标 | 就绪来源 | 覆盖关系 |
| --- | --- | --- |
| `14/4000/4000` | `14/4000/4000` | 精确子瓦片 |
| `14/4001/4000` | `13/2000/2000` | 父级为相邻子区提供覆盖 |
| `13/2001/2000` | `12/1000/1000` | 更粗父级为另一区域提供覆盖 |

在 `14/4000/4000` 区域，三个来源同时进入 `shown`，均已显示 1000 ms。该结果证明重叠可跨越淡入期；它没有给出真实 GPU 每像素着色次数。原始浏览器诊断缺少完整 `shown` 地址与 opacity，实际轨迹的重叠面积和持续时间需要新增观测。

通常每个有道路的瓦片包含面和线两次绘制。统计“数据层级重叠”与“绘制 pass 数量”时需要分别计量。

## 近处细节的选择问题

`selection.ts:22` 将最大目标层级限制到 `floor(view.zoom)`。相机倾斜后，屏幕近处的每像素地面尺寸变小，允许的最大目标层级仍使用全局整数 zoom。

`selection.ts:49` 的合并顺序首先按父节点数据层级排序，再按投影中心距离均值排序。循环以 80 个叶片为目标，近处高层级节点也会参与合并。屏幕中心距离与屏幕像素贡献、局部几何误差分别具有不同含义。

| pitch / bearing | 预算合并前的目标 | 当前目标 | 当前目标数 |
| --- | --- | --- | ---: |
| 0° / 0° | z15×77 | z15×77 | 77 |
| 40° / 0° | z14×8、z15×102 | z14×22、z15×58 | 80 |
| 60° / 0° | z13×5、z14×75、z15×92 | z13×15、z14×61、z15×3 | 79 |
| 60° / 45° | z13×4、z14×73、z15×93 | z13×14、z14×61、z15×3 | 78 |

“预算合并前”仅通过探针将 `maxLeaves` 参数设为 Infinity 得到，承担合并影响的对照职责。

![当前目标编号和层级](../evidence/tile-audit-2026-09-15/selection-pitch60-numbered.png)

此图由当前选择器和相机矩阵计算，颜色表示目标层级；右表列出全部 79 个目标 XYZ 地址。它是静态分析图，实时地图标注的设计位于方案文件。

相机中心行的局部数据采样尺度约为 zoom 15；屏幕高度 90% 处的局部尺度约为 zoom 15.65，99% 处约为 zoom 15.77。z14 数据在这些区域使用更粗的几何与面细节。512 像素面纹理提高采样分辨率的范围为 z15–z17；z14 面纹理为 256 像素。道路宽度按视图计算，几何细节仍取决于源数据层级。

07:13 浏览器记录在 50.698 秒 `targetMissing=0`、`displayZoomGap=0`，目标层级仍为 z13×15、z14×61、z15×3。`displayZoomGap` 衡量目标与实际来源的差值；目标本身的屏幕质量需要独立评价。

## 雾、远处加载和预取

`selection.ts:14` 使用中心地面距离截止圆：pitch 60° 时 `cutoff=2.8×cameraDistance`，`fogStart=0.58×cutoff`。本例截止约 21.07 km，起雾约 12.22 km。

| 屏幕中央列位置 | 地面距离 | 雾混合系数 |
| --- | ---: | ---: |
| 顶部 0% | 22.06 km | 100% |
| 顶部 5% | 15.84 km | 36.4% |
| 顶部 10% | 11.71 km | 0% |

全屏地面采样共 33280 点，完全入雾 968 点（2.9%），渐隐带 3424 点（10.3%）。该视图大部分顶部地面仍在加载边界以内。

当前代码已执行 AABB 最近地面距离与视锥剔除。边界瓦片只需部分相交即可保留，祖先还可横跨边界。TSL 雾混合改变颜色，完整瓦片的几何提交与片元处理仍有成本。

`engine.ts:143` 起为每个目标组织目标、下两级覆盖、下三级和下五级基础覆盖及邻接圈；`engine.ts:186` 起组织下三级和下四级全方位预热。当前视图首次规划准入 222 个条目，其中 79 个目标、143 个覆盖或预热条目。这是首次准入量，后续缓存、HTTP 204、视图与预算会改变实际请求量。

`engine.ts:176` 的显式未来视图预取按各自的视图与时效组织，可处于当前截止圆之外；城市目的地预取需要单独计量。

## 调度、资源和可观测性

| 代码事实 | 体验或验证影响 |
| --- | --- |
| `pump()` 以数值优先级组织批次，普通状态先分配约 2/3 槽位，再补充目标 | 本例空流水线的第一批为 8 个祖先、4 个目标；仅余一个槽位时选中祖先，目标槽位比例在小批次下缺少保证 |
| 自由运动前视预测仅对缩小速度启用；城市路径单独预取 | 自由平移、转向主要依赖邻接圈与全方位预热 |
| Worker 排队采用 FIFO，视图改变后排队任务保持原顺序 | 近处新需求可能等待较早进入的后台工作；具体延迟需要实时任务年龄观测 |
| 失去需求的请求继续传输，返回后可直接丢弃；Worker 结果在上传阶段再判断需求 | 部分网络和构建工作可能对当前画面没有贡献，浪费比例尚待统计 |
| `ready` 非空条目包含 GPU surface，预取也可执行 GPU 上传 | 预取会使用 GPU 驻留空间与上传预算；缓存满本身只表示达到预算，收益需结合命中与有效上传计量 |
| CPU/GPU 瓦片计数在 surface 创建时增加 | Worker 中、待上传结果与网络在途 buffer 需要独立的流水线内存计数 |
| 选片帧跳过上传，其余帧最多一张；全局规划最小间隔 45 ms，突变可立即规划 | 相机突变频度与上传进度有耦合，卡顿和就绪时间需要逐阶段验证 |
| `levels` 来自目标，`outgoing` 为 shown 中所有非目标，`maxLodDelta` 为全局最高减最低 | 面板“过渡”可能包含稳定祖先覆盖；“邻接层级差”实际是全局范围；这些字段不能直接回答实际重叠层数 |
| 以覆盖缺口和目标差值判断就绪 | 地面连续、近处细节充分、遮挡绘制成本分别需要独立断言 |

## 公开实现核查

本轮直接读取公开源码，并保存 [来源 URL 与 SHA256](../evidence/tile-audit-2026-09-15/public/sources.json)。

- [MapLibre covering_tiles.ts](https://github.com/maplibre/maplibre-gl-js/blob/main/src/geo/projection/covering_tiles.ts)：按相机、瓦片距离、局部期望 zoom 和视锥选择瓦片，高倾角行为有可配置函数。
- [MapLibre painter.ts](https://github.com/maplibre/maplibre-gl-js/blob/main/src/render/painter.ts)：`getStencilConfigForOverlapAndUpdateStencilID()` 明确通过 stencil 遮罩处理父子瓦片覆盖区域；普通瓦片也有 clipping mask。
- [3DTilesRendererJS TilesRendererBase.js](https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/master/src/core/renderer/tiles/TilesRendererBase.js)：具有可见性、误差、距离优先级、独立下载/解析队列与 LRU。
- 本地 Three.js 0.185.1 `WebGPUPipelineUtils.js` 包含材质 stencil 状态到 WebGPU 管线的映射。具体地图 mask pass 的可用性、透明过渡与性能仍需实现验证。
- MapLibre `main/src/source/source_cache.ts` 在本轮请求返回 404，本报告对该文件保留未读取状态。

LOD、视锥剔除、预测预取、分层缓存与预算回收构成成熟的地图/场景流式加载范式。最高性能取决于数据复杂度、设备、网络、视图和画质要求；本次没有同环境、同画质的多引擎性能比较证据。当前问题集中于误差分配、绘制覆盖和流水线预算。
