# Nova AI Session Log

更新日期：2026-09-15

## 定位

本文件是 Nova AI 会话记录的轻量入口、规则和索引。详细记录按日期拆分到 `docs/ai-sessions/YYYY-MM-DD.md`，避免单文件持续膨胀。

它不是正式事实库，也不是架构决策记录。`docs/project-state.md` 是低 token 当前状态入口；正式项目状态仍以 `PROJECT.md`、`TASKS.md`、`tasks/Txxx-*.md`、`KNOWLEDGE.md`、`docs/architecture/`、`docs/architecture.md`、`docs/decisions/` 和 `docs/decisions.md` 为准。

## 行业对应

这种机制通常接近以下几类工程文档：

- `Engineering Log` / `Project Journal`：记录项目推进过程中的重要上下文。
- `Meeting Notes`：记录一次讨论的输入、结论和行动项。
- `Decision Log` 的补充材料：保留讨论线索，但不替代 ADR 或正式 decisions。
- `AI Work Log` / `Agent Activity Log`：记录 AI 辅助开发时的人类意图、AI 判断、执行结果和风险提示。

Nova 采用的名称是 `AI Session Log`，强调它是 AI 会话层面的纪要，而不是产品事实或架构批准本身。

## 文件结构

- `docs/ai-session-log.md`：规则、读取策略和最近记录索引，只保持轻量。
- `docs/ai-sessions/YYYY-MM-DD.md`：按日期追加的详细会话记录，保留用户原话和 AI 结论。
- 如果单日记录超过约 100 KB 或 1,500 行，可拆为 `docs/ai-sessions/YYYY-MM-DD-02.md`，并在本索引中登记。

## 读写规则

- 决策会话应读取本文件，并按需要读取最近或相关日期的详细记录。
- 实施会话默认读取本文件；只有当前任务涉及人工验收失败、方向争议、架构重置、上下文污染风险，或用户明确要求时，才读取相关日期详细记录。
- 所有项目内 AI 操作会话结束时都应追加一条详细记录，包括普通实施任务，例如“执行 T025”。
- 普通实现细节、完整命令输出和稳定事实不要写入会话记录；应分别写入任务文件、evidence、`KNOWLEDGE.md` 或 decisions。
- 用户自然语言输入应优先保留原话；超长日志、代码、附件或敏感信息不得整段复制，应记录用途、文件路径、摘要或脱敏片段。
- AI 结论应记录最终判断、关键依据、执行结果、验证结果和后续动作，不记录长篇思考过程。
- 任何 AI Agent 不得把会话记录中的推测直接升级为事实；要先回到代码、测试、evidence 或人工确认。

## Token 控制策略

- 默认只读 `docs/ai-session-log.md`，不要默认通读 `docs/ai-sessions/` 全量历史。
- 当前状态先读 `docs/project-state.md`；历史追溯再读本文件和相关日期分片。
- 查找历史时优先使用 `rg` 搜索任务号、关键词、日期或主题，再打开命中的局部文件。
- 只需要最近上下文时，读取当日文件尾部或最近 3-5 条记录。
- 本索引只保留最近记录和关键主题入口；详细历史留在日期文件中。

## 记录格式

```md
### SYYYY-MM-DD-NNN — 主题

- 会话类型：决策会话 / 实施会话
- 关联范围：Txxx / docs / package / decision / unknown
- 用户原话：

> ...

- AI 结论：
  - ...
- 执行与验证：
  - ...
- 后续动作：
  - ...
- 正式状态影响：
  - ...
```
