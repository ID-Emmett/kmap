# Kmap AI Session Log 2026-09-24

### S2026-09-24-001 — 修复惯性打断后释放速度沿用拖动速度

- 会话类型：实施会话
- 关联范围：packages/map3d/src/interaction、packages/map3d/test/mapInteractions.test.ts
- 用户原话：

> 修复以下问题
> 1：鼠标左键按住拖动后迅速松开会有阻尼过渡这是标准操作，但此时再次左键过渡会立刻停止被交互接管，松手后会继续执行上一轮的阻尼过渡，这不合理，应该是以最新的状态交互为准
>
> （追加说明）当前测试还是存在问题……鼠标快速拖动后，还过渡未停止时，继续快速按下拖动，此时拖动任意方向松开后，地图会朝着第二次拖动的方向运动，实际上第二轮拖拽时鼠标朝某处拖但是最终是静止时松开鼠标，地图还是会快速朝该方向运动了。

- 复现与根因（真实 Chromium + playground `127.0.0.1:6661`，Playwright 真实指针事件；假时钟单测复核）：
  - 缺陷一：释放速度窗口以"最后一个位移样本"结尾，拖动结束后静止到松手的时间不参与窗口。实测拖动 200px 后静止约 309ms 再松开，松手后仍滑行 `0.00414`（约 96px）。这是用户追加说明指向的主缺陷。
  - 缺陷二：样本裁剪会丢弃窗口起点之前的样本，窗口塌缩到最后 12.6ms 的短促位移；亚帧拖拽（2ms 内 50px）的速度会被放大到 `MAX_PAN_PX_PER_SECOND` 钳制上限。
  - 反向验证：按下接管后原地不动再松开、以及按下停顿 300ms 再松开，均不产生惯性；松手时指针仍在移动时惯性正常。
- 修复内容（`packages/map3d/src/interaction/`）：
  - `pointerVelocity.ts`：`estimateReleaseVelocity` 改为窗口内时间加权平均速度——窗口为 `[endTimeMs - 120ms, endTimeMs]`，越出窗口的位移按时间比例截断，窗口内无位移的静止时间只参与分母；`endTimeMs` 由调用方传入（释放惯性传松手时刻，运动快照沿用最后样本）。
  - `pointerVelocity.ts`：样本裁剪保留"窗口内样本 + 窗口起点之前最近的锚点样本"，锚点定义手势起点和窗口起点，避免窗口塌缩。
  - `inertia.ts`：新增 `MIN_RELEASE_WINDOW_MS = 32`（约两帧 @60Hz）作为窗口时长下限；指数衰减、起停阈值、速度上限等既有调校值不变。
  - `mapInteractions.ts`：`#startInertia` 以松手时刻作为速度窗口终点。
- 执行与验证：
  - `packages/map3d/test/mapInteractions.test.ts` 新增 3 例（拖动后静止再松开不进入惯性、松手前仍在移动时保持惯性且静止越久越弱、亚帧拖拽不放大到钳制上限），map3d 全量 203 例通过（33 个文件）；`pnpm ai:check`、`git diff --check` 通过；交互模块无类型错误。
  - 真实浏览器复测：移动中松手滑行 `0.00525`（约 122px，惯性保留）；静止 308ms 后松手滑行 `0`（修复前 `0.00414`）；"先惯性 → 按下反向拖动 → 停止 300ms → 松开"滑行 `0`（修复前沿新方向飞出）。
