# Kmap Streaming Map Architecture

更新日期：2026-09-16。生产验收入口为 `http://127.0.0.1:6661/`，支持 WebGPU 与 WebGL2。

## 入口与职责

`Map3D` 使用 `packages/map3d/src/streaming/engine.ts`。Playground 通过 `@kmap/map3d` 接入。

| 模块 | 职责 |
| --- | --- |
| `address.ts` | XYZ、canonical 网络身份、世界副本与父子关系 |
| `coveringTiles.ts`、`groundVisibility.ts`、`fog.ts` | 统一目标层级、视锥地面交集、雾距离与数量预算 |
| `renderCover.ts`、`availability.ts` | 可用来源与互斥覆盖、增量祖先索引 |
| `fallbackDemand.ts` | 缺口、过粗来源和有用在途祖先的有限补充需求 |
| `engine.ts` | 视图、当前需求、预测需求与帧提交协调 |
| `tileStore.ts` | 编码数据、构建产物、GPU 资源、在途预留与 LRU 回收 |
| `pipeline.ts`、`workers.ts` | 网络、Worker、上传阶段准入及取消 |
| `overlayCache.ts` | canonical 补充响应共享、租约取消与 8 MiB / 128 项缓存 |
| `labels/` | Worker 候选、SDF 字形、稳定碰撞和全屏字形实例批次 |
| `globe/` | 矢量几何球面投影、曲面细分、球面覆盖和统一相机 |

| `buildings.ts`、`buildingSurface.ts` | 建筑屋顶/墙面合批、孔洞、米制高度、分类色、深度遮挡与局部区域裁剪 |
| `tileSources.ts` | 补充数据长度前缀包、祖先坐标转换与 source-layer 映射 |
| `diagnostics.ts`、`tileDebug.ts` | 队列、字节、真实来源编号与屏幕投影 |

## 当前显示与选片契约

- 数据采用 256 CSS 像素 XYZ 缩放语义。面由矢量几何绘制，区域背景纹理为 1×1。
- 理想目标、限额目标和当前显示来源分别保存。可用目标直接显示；目标等待时查询已就绪子级和最近可用祖先。
- 地面区域具有单一来源。完整瓦片使用地面边界与线着色器裁剪；部分区域写入 stencil，面与线使用相同来源引用。瓦片透明度固定，就绪内容在帧边界直接接替。
- 面批次由互斥矩形构成，颜色绘制直接写入有效区域。带有道路的部分来源同时写入 stencil 归属，道路通过 EQUAL 测试使用该归属。每个来源实例持有独立 PatchGeometry，区域属性缓冲按实际容量复用；该几何容量计入 CPU/GPU 字节。
- 雾中心、起止距离与颜色节点属于 Three.js renderGroup，每次渲染使用当前相机参数。
- 当前视图的目标瓦片使用同一整数层级；目标数量超出容量时整体选择一个父层级。视锥和雾剔除先于细分，叶片以地面/视锥精确交集核验。
- 最大俯仰角为 75°。20° 至 45° 平滑调整距离雾，45° 至 75° 继续收紧起止距离；75° 时屏幕中心列顶部 40% 处达到完全入雾。CPU 以 smoothstep 不透明度 98% 剔除，TSL 使用同一距离曲线。
- 建筑采用每瓦片一个几何批次，height/min_height 为真实米并进行 Mercator 纬度补偿；kind 可配置分类色。屋顶保留孔洞，墙面保留高度梯度，深度缓冲处理建筑互相遮挡。Playground 在 zoom ≥ 15.74 显示建筑。
- 线宽默认使用米制；widthStops/widthBase 进行连续指数插值。线宽在地图平面中展开并通过相机透视投影；dashArray 使用线宽倍数表达实线和间隔，支持两项虚线和四项点划线。
- 线宽/虚线表在顶点阶段查找，离散样式采用 flat 插值；导数在裁剪前求值，细密虚线按平均覆盖抗锯齿。样式表尺寸由图层数量确定。
- Playground 的省界来自 kye_admin_pro/border，最大原生层级 14；海洋使用 kye_water_ocean 与主源为空时的 kye_water。更细视图转换祖先几何。主数据和补充数据共享网络槽位与 Worker；补充请求通过引用租约取消，HTTP 次数按真实请求计量。
- 文字以半开区间归属 render cover，布局每 64ms 最多一次；屏幕网格处理碰撞，优先级、名称去重与放置保留确定显示集合。点锚点按稳定标识保留；浮动原点和道路线段方向逐帧投影，字形共享一个实例批次。
- minZoom=0 的数据源默认使用球面矢量瓦片，4.5–5.5 级连续改变同一几何的球面权重；globe=false 使用平面视图。瓦片面与线路由 Worker 在低层级细分，曲面、地名与基础极区共用一个场景和相机。
- 覆盖解析最多查询两级已加载子级，祖先查询延续至数据源最小层级。空数据登记为 HTTP 204；内容覆盖继续查找有内容的祖先。
- 原始来源层级差与尚待细化的层级差分别记录。已确认空数据目标具有独立计数。

## 调度与资源契约

- 网络上限 12，Worker 上限 4，待上传上限 8，当前目标上限 128，预测需求上限 32，必要补充覆盖请求上限 8。
- 默认条目上限 256，CPU/GPU 各 256 MiB。每帧至多上传一张纹理，同时检查字节与主线程阶段预算。
- 当前细节、必要覆盖与预测获得有界网络机会。过期上传产物释放后归还阶段容量；过期构建结果关闭位图。未完成的过期网络请求使用 AbortController 取消。
- 缺口与超过两级的来源误差共享八个补充请求名额，缺口优先。可以补足缺口的在途祖先保持当前需求；已确认空目标保留独立数据状态。
- 常规队列每六次分配四次当前细节、一次补充覆盖、一次预测。检测到每秒至少一级缩放或四个瓦片跨度的平移后，500 ms 内三类需求轮转。网络、构建和上传分别推进此轮转；空类别由当前最高优先级工作使用。上述份额与阈值属于项目参数。
- 网络响应通过流读取累计解压字节，保留分块及最终合并数组的预算。单响应上限 16 MiB；Worker 根据输入大小登记构建预留。CPU 数值包含可归属数据与预留估算，浏览器与驱动内部内存独立于该估算。
- 资源字节包含背景 mipmap、面/线/建筑几何、线样式表与建筑裁剪表。显示依赖受回收保护。内存回收保留零字节空响应记录；条目数量回收仍可淘汰空记录。
- 文字候选计入瓦片 CPU 预算。全局字形资源独立限制为 4 MiB atlas、32 个 PBF range 与 8,192 个字形实例；海洋/行政区响应共享缓存独立限制为 8 MiB。球面几何和区域细分缓冲计入瓦片 CPU/GPU 预算。
- 相机预测受有限时间窗和数量控制。附近概览通过逐级合并完整视域保持数量上限；城市路径按请求到可显示的延迟提供近处细节视图及更远的概览视图。
- 自由运动预测使用请求到可显示的 P95 加 100 ms，约束在 200～650 ms；倾角和方位参与未来视图。预测粗级完整覆盖未来视域，并与预测细节共同服从 32 个需求限额。
- 数据就绪只刷新需求和覆盖；相机改变刷新空间选择。就绪祖先索引按资源增减维护。

## 接口与观测

- `prefetchViews` 接受视图、时效、优先级与数量限制。相机城市飞行保持 van Wijk / Nuij 路径。
- `observeFrames` 在真实 render 调用完成后触发；`getFrameState` 提供帧编号、CPU 分段、覆盖版本与资源计数。
- `getTileSnapshot` 提供当前目标、理想目标、来源分区和条目用途。`getTileDebug` 提供来源编号与屏幕多边形。
- `auditPixels` 同步对照屏幕像素和源面纹理，服务于专项视觉定位；其回读开销单独记录。最近 32 次失败保留时间、瓦片键、请求/构建阶段和原因。
- Playground 提供编号开关、城市往返、连续交互、录像、原生帧率对照、浏览器 RAF 基线与 JSON 导出。
