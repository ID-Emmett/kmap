# 瓦片、文字与鼠标缩放验证

日期：2026-09-19。入口：`http://127.0.0.1:6661/`。

## 当前实现

- 当前视图采用单一目标层级；相机缩放具有整数层级滞回。平移优先预热同级邻居，预测上限为 32。
- 已显示的完整祖先覆盖保持到目标就绪；目标在帧边界接替。父子来源通过互斥区域和模板裁剪绘制。
- 主源空响应逐级查询有效祖先，几何映射到当前目标区域；`primaryFallbacks` 列出目标地址与实际主数据地址。原始响应按 URL 共用有界缓存和在途请求，送入 Worker 的缓冲独立持有所有权。
- KYE 主源缺少的 boundary、waterway、landcover_0 使用 z6 相应图层补全。相交包围盒筛选限制祖先要素处理范围，GPU 按目标瓦片区域裁剪。
- 线宽与虚线采用固定 BufferNode，绘制时绑定当前瓦片数据。
- 文字采用稳定 key、世界锚点和碰撞放置优先级。已显示点标签具有 350ms 的候选缺口保留期限；字号、层级或可见性配置仍参与布局。文字与图标共用一个 SDF 批次。
- 国家在 z0～4.5 显示，省名在 z3.5～6 显示，省会在 z6 起显示，普通城市在 z7 起显示；上界为开区间。省会采用红色同心圆图标。标签密度由屏幕碰撞和数量上限控制。
- 滚轮逐帧维持鼠标下的地理锚点。平面采用射线差校正；地球及过渡阶段采用与地图投影一致的迭代校正。

## 数据事实

[data.json](data.json) 记录请求 URL、HTTP 状态、字节数及要素类型。台湾东侧 `7/107/55` 主源返回 204，相邻 `7/106/55` 有 173 个 grass 要素；`6/53/27` 提供有效地表、河流、边界和地名。`place/class=state` 提供省名，`place/class=city` 且 `capital=1/2` 提供省会分类。

祖先数据的细节精度由源层级决定。空主源区域具备连续地表覆盖；道路、建筑和城市名称的可用精度取决于上游实际数据。`primaryFallbacks` 显式记录该数据边界。

## 缓存与面板指标

| 指标 | 当前计量含义 | 如何理解 |
| --- | --- | --- |
| 预热动作 | 提前请求预计即将进入视图的瓦片 | 用有限网络和内存换取平移时的响应速度 |
| 驻留 | 当前被显示覆盖引用的就绪来源数量 | 同一来源可服务多个裁剪区域 |
| 预热 / warm | 已 ready 且当前未显示的条目 | 包含预取结果与刚退出视图的可复用内容 |
| 冷缓存 / cold | 已有 CPU 数据，等待 Worker 或 GPU 上传的条目 | 本面板具体为 decoded + upload；复用仍需后续处理 |
| 冷启动 / 冷加载 | 当前运行实例缺少所需缓存的加载过程 | 与面板的冷缓存条目数具有不同含义 |
| 命中 | 已就绪 surface 重新进入需求集合的累计次数 | 表示直接复用绘制资源的机会 |
| 未命中 | 为新需求创建条目的累计次数 | 包含可见、回退和预测需求 |
| 命中率 | 命中 ÷（命中 + 未命中） | 为引擎需求统计；浏览器 HTTP 缓存另行管理 |
| 条目 / 上限 | 当前条目数 / 允许的最大条目数 | 条目包含各处理阶段；默认 256 |
| 淘汰 | 预算回收释放条目的累计次数 | 淘汰优先处理低优先级、较久未使用内容；当前绘制依赖受保护 |
| CPU / GPU 预算 | 瓦片归属数据与资源的统计预算 | 默认各 256 MiB；CPU 包含在途预留。原始响应缓存、字形 atlas、浏览器及驱动内存具有独立边界 |
| 预算压力 | 统计资源超过预算的状态 | 应结合淘汰频率、细节缺口和加载时延观察 |
| 目标 / 提交 | 目标瓦片数 / 已显示来源数 | 父级可覆盖多个目标，二者通常不同 |
| 目标缺失 | 尚未 ready 的目标条目数 | 已有祖先时画面仍可完整 |
| 覆盖缺口 | 可见区域中缺少可用来源的单元数 | 稳态应为 0；首次数据到达前可大于 0 |
| 显示层级差 | 目标层级与较粗来源之间的最大差 | 正值代表加载期间的较粗覆盖 |
| primaryFallbacks | 空主源目标使用的有效祖先地址 | 反映上游数据可用性，独立于目标调度是否完成 |
| 目标层级 / 来源层级 | 需要的层级 / 当前提交来源的层级 | 多级来源可以分布在不同区域；父子区域使用互斥裁剪 |
| 理想 / 限额合并 / 雾剔除 | 原始选片数 / 容量降级减少数 / 雾裁剪数 | 表示视域和资源预算对选片的影响 |
| 排队 / 活跃 / 上传 | 各流水线阶段的条目数量 | 持续积压表明对应阶段成为瓶颈 |
| 请求 / HTTP / 重试 / 取消 / 错误 | 逻辑瓦片加载与实际网络操作的累计数 | 一个逻辑加载可使用多个数据源；共用缓存可减少实际 HTTP |
| 请求 P95 / HTTP P95 | 完整请求到就绪 / 单次 HTTP 的 95 分位耗时 | 前者包含后续处理和等待，后者主要反映网络 |
| FPS / 帧间隔 | 浏览器实际渲染回调频率与间隔 | 受显示器、浏览器调度、CPU、GPU 共同影响 |
| CPU P95 | 95% 采样帧的主线程处理耗时不超过该值 | 可用于观察尾部卡顿；与 GPU 时间、整体帧间隔分别计量 |
| 规划 / 覆盖 / 回收 / Worker / 上传 | 对应阶段的处理时间 | 用于定位计算、构建或资源提交瓶颈 |
| Draw calls / 三角形 / 对象 | 提交批次数、几何量和场景对象数 | 结合帧耗时评估渲染成本 |
| 文字候选 / 放置 / 布局时间 | 参与布局数量、显示标签数量及 CPU 布局耗时 | 放置数受碰撞和密度限制 |
| 字形 / 字体请求 / 缺字 | atlas 字形数、待加载 range 及上游缺字 | 字体到齐后标签可完成显示 |

## 平移中轮廓细化的含义

预热与冷缓存表示数据准备状态，数据地址仍然包含 z/x/y。目标数据到达前，地图可显示祖先的概化海岸线；目标就绪后使用更精细几何。同一帧可提交不同层级的来源，每个有效区域具有唯一覆盖归属。当前完整祖先覆盖保持到目标就绪，从而限制中间层连续接替；同级邻居预热减少进入新区域时等待详细瓦片的机会。

MapLibre 的目标选择、父子回退、矢量模板裁剪与 LRU 机制依据见 [固定版本研究](../../research/industry-tile-streaming-2026-09-16.md)。

- 同状态像素对照采用 480×270 回读，RGB 任一通道差异大于 16 时计为变化像素，单次超过 120 像素记为异常。同步回读阶段与性能阶段分别执行。
- 真实鼠标操作、台湾、省名、省会和倾斜场景截图结合程序指标进行检查。浏览器采样具有明确的场景与采样边界。

冷加载使用 806×1272 视口、150ms 延迟、500,000 B/s 下载速度和关闭浏览器缓存；首次到达前有 24 个覆盖缺口，最终缺口为 0。首次数据到达前的等待属于加载过程。采样覆盖海面点的连续性及同状态重复渲染。

实际鼠标滚轮从 z10 到 z11（pitch 55、bearing 35），指针地理锚点误差为 7.8×10⁻¹⁰ 个 Mercator 等效像素；球面过渡 z4.7 到 z5.7（pitch 35、bearing 25）误差为 0.0156 像素以内。真实拖拽保持 zoom 不变，结束时目标缺失与覆盖缺口均为 0。省名及省会红圈另有全分辨率截图。

结论范围由上述场景、阈值与采样点定义。台湾空主源区域的细节精度由有效祖先数据决定。
