# 道路宽度与快速交互修复验证

日期：2026-09-15。实际入口：<http://127.0.0.1:5173/>。会话：S2026-09-15-002。

## 结果

当前道路由 GPU 中心线实例绘制，线宽按当前视图计算。首屏、快速缩放与平移、旋转、倾角切换、城市往返的最终 WebGPU 验证全部通过本次工程门槛。1155 张连续采样图与 477 张关键窗口密集采样图完成模型视觉审查，采样中巨大道路块和初始化后交互白块出现次数为 0。初始化与运动中存在可见的渐进细化。

## 问题定位与实施

用户提供的两张截图分别记录快速交互中的局部巨大道路块，以及初始化中粗大地图与细节瓦片同时显示的画面。附件路径保存在本次会话记录中。

道路烘焙在线纹理中时，祖先纹理的空间放大会同步放大道路笔画。数据层级相差三级时，纹理中的笔画可放大八倍。初始祖先覆盖和快速运动期间的祖先回退均会触发这一机制。请求、Worker 与上传就绪顺序还会影响粗细数据共同出现的持续时间。

当前实施包含以下部分：

- Worker 复用 MVT 图层解码，输出面纹理与道路中心线数组；中心线使用 0.25 原生 CSS 像素容差简化，TypedArray 按实际容量分配。
- 每瓦片以一个实例胶囊 Mesh 绘制道路，TSL 处理圆端点、抗锯齿、瓦片裁剪和视图线宽。`2 ** (dataZoom - viewZoom) / 256` 保证相同视图下各数据层级具有相同地面线宽；共享节点图与独立对象参数控制材质成本。
- 数据源最细三级面纹理使用 512 像素，其余为 256 像素。CPU/GPU 统计和上传准入计入实际纹理及实例数组字节，每帧最多上传一张，选片与上传分帧。
- 当前目标与必要近层覆盖优先上传；当前需求与预取分别准入，384 条目硬上限在创建时执行。未显示的低优先级就绪缓存可为必要需求和路线预测腾出空间。
- 地面截止半径内保留基础覆盖并预热下三级、下四级的全方位数据，支持旋转与倾角变化。细级缓存参与覆盖解析，嵌套覆盖面积采用互斥统计。
- 自主缩小预测未来 0.6 秒，缩小幅度上限 1.5 级；显式城市路径预取前方 0.5 秒和 1.1 秒视图。请求、预取与缓存均受距离、并发和字节预算约束。
- 滚轮使用 80 ms 时间常数按实际经过时间推进，约 240 ms 完成输入量的 95%；60/120/170Hz 回归验证同一时间的相同轨迹与最终 zoom。
- Playground 保留现有面板与城市飞行，增加“首屏与快速交互验收”；录像支持 H.264/MP4 与 VP8/WebM，DOM 诊断存放摘要。

完整当前机制见 [架构](../../architecture/nova-tile-engine.md)，公开来源见 [研究记录](../../research/streaming-rebuild-public-sources.md)。本次依赖清单保持现有版本。

## 环境与测量口径

- Windows，Intel i5-13600KF，NVIDIA RTX 4070 Ti，驱动 32.0.15.9186。
- 真实 Chromium 内嵌浏览器，Three.js WebGPU，2560×1305，DPR 1，真实 KYE MVT。
- 浏览器 HTTP 缓存开启。首屏运行重新创建引擎；324.0 ms 与 1276.9 ms 是诊断采样中首次满足条件的时间。
- 性能使用逐 RAF 回调间隔。录像目标 60 FPS、H.264/MP4；三段实际编码帧率约 57–58 FPS。10Hz 诊断与录像图像共同用于覆盖、细节及视觉核查。
- 资源数值是引擎跟踪的 CPU/GPU 瓦片资源估算，包括面纹理、mipmap 与实例数组；浏览器进程及驱动总内存另有口径。
