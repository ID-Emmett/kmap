# 运动瓦片白闪与留白验证

入口：`http://127.0.0.1:6661/`。使用真实 KYE 网络、WebGPU/WebGL2、RTX 4070 Ti、2560×1305、DPR1，Inspector 开启。原始 JSON 与源码 SHA256 见 [verification-summary.json](verification-summary.json)。

## 已验证原因与当前实现

1. **绘制通道的模板编号。** Three 0.185.1 `WebGPUBackend.draw()` 使用 `currentStencilRef` 缓存动态编号；GPU 新通道的初值为 0。前一通道的末次编号与当前通道首个部分瓦片相同时，缓存会省略绑定，导致区域写入 0。后续内容的 EQUAL 测试出现缺块或越界绘制。相机移动改变绘制顺序，可表现为连续白闪；固定顺序可表现为持续留白。当前全局底面在每个通道先绑定保留编号 0，部分区域使用 1～255；底面模板写掩码为 0，保持模板内容。
2. **子区域可见性。** 父目标地址相同时，已加载子区域与视锥的交集仍随相机改变。当前在目标依赖回退资源时刷新显示覆盖，涵盖待加载和已确认空响应的目标。
3. **整数缩放滞回。** 目标层级直接进入平面选片；向下 0.18、向上 0.08 的门槛作用于实际请求与覆盖。回归覆盖 z15.99↔16.02 往返及门槛两侧。
4. **快速缩小的驻留覆盖。** 覆盖解析沿就绪资源的祖先索引查找任意深度子级。四级缩小用例只访问 17 个节点，保留已有区域。请求数量、缓存和资源预算保持现有配置。

平面模板初始化复用陆地底面批次；球面使用同一两三角形批次，关闭颜色写入。生产运行时每帧执行一次地图绘制，逐像素双绘制只存在于显式开发验证入口。SDK 继续采用 TSL / Node Material，无新增依赖。

## 因果对照

- 720 帧运动探针：同一相机与资源状态连续绘制两次，124 帧出现超过阈值的像素差异。GPU pipeline ready 探针未出现跳过绘制。启用通道起始编号的控制实验中，720 帧异常为 0。
- 两区域定点探针：倾角 35°，编号 1/2，部分区域颜色设为洋红。关闭起始编号时连续四帧采样为陆地底色 `[230,244,243,255]`；启用起始编号后连续四帧为正确颜色 `[255,0,255,255]`。这组数据在相机、网络和瓦片内容固定时复现持续留白。
- 原始对照路径与哈希列于摘要的 `probes`。实际输入在默认游乐场进行，探针结束后重载页面恢复正常状态。

## 浏览器矩阵

开发入口为 `?capture=motion` 和 `?renderer=webgl2&capture=motion`，脚本为 `apps/playground/src/streamingMotionBenchmark.ts`。

每后端包含 720 帧连续 pan/zoom/pitch/bearing、160 帧整数门槛往返、24 个静态视图（z5/8/10/13/15/16/17/20 × pitch0/60/75），共 904 次相同状态的重复绘制对照。图像回读宽 480px；单通道差值超过 16 计为差异像素，超过 120 个差异像素记为异常。两区域定点探针补充固定错误图像的检测。

静态视图要求目标待就绪数与覆盖缺口连续 8 帧为 0。冷启动压力轨迹即时移动，尚未收到首批网络数据时会存在暂时缺口；该阶段逐帧记录在 `samples` 与 `coldStressUncoveredFrames`。持续留白以稳定视图收敛、图像和定点颜色共同判定。

30 秒性能轨迹在独立阶段执行，无图像回读或额外绘制；文字开启。完整结果、超阈值像素数、收敛状态、资源峰值和错误均由摘要保留。两个后端的联系表完成模型视觉检查。
